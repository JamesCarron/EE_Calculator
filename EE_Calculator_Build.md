# EE Calculator — build task summary

## Goal

A self-contained web tool for everyday EE and PCB calculations, built as a single HTML page generated by Python, set up as a git repo with a pixi environment and committed incrementally. Originally scoped around a resistor divider calculator (feature set modelled on https://sagecalculator.com/resistance-divider-calculator/), later broadened after a feature comparison against the Saturn PCB Design Toolkit.

## Current state

Done and verified. `EE_Calculator.html` is generated by `build_page.py` (`pixi run build`) and opens straight from the filesystem — no server, no network. Eight top-level tabs: Ohm's Law, Resistors, RC Filter, Reactance, PCB, Impedance, Crystal, Utilities. The Resistors tab holds four sub-tabs — Divider, Series / Parallel, LED Resistor, Accuracy — and is the only tab that shows the E-series selector (default E96), which feeds the divider suggestions and the LED next-value-up.

**Solvers write into their input boxes.** Where a tab solves for missing values, the answer goes into the relevant field, tinted and marked as calculated, instead of being repeated in a separate results list; only derived quantities with no field of their own (ratios, currents, powers, E-series suggestions) go to the results list. This applies to Ohm's Law, the divider, RC, LED, crystal, ppm and trace width. Two rules keep it honest: every recalculation first empties the fields still tagged `computed`, so a stale answer can never be read back as an input; and typing in a field drops the tag before the calculator runs, so a user-entered value survives that clearing and becomes an input. A one-line legend under the tab bar explains the tinting.

**Copy to clipboard.** Every card has a Copy results button that serializes that card's inputs (marking which were calculated) and its results — including the divider's pair table as TSV — to plain text. One handler serves all 19 cards by reading the DOM back out, so a new card gets a working button just by existing. `navigator.clipboard.writeText` with an `execCommand` fallback for browsers that withhold the async clipboard on `file://`.

**Divider solver** takes any three of Vin, Vout, R1, R2 — plus optional total resistance and a constant midpoint load current (KCL: I_R1 = I_R2 + I_load) — and solves whatever is missing: three of four → the fourth (all four → Vout check mode); one leg + total → the other leg; Vin + Vout + total → both exact legs (unloaded R1 = (Vin−Vout)·T/Vin; loaded, the smaller root of IL·R1² − (Vin+IL·T)·R1 + (Vin−Vout)·T = 0); Vin + Vout alone → a load-aware search of E-series pairs ranked by loaded-Vout error, steered toward the total when given.

**Accuracy sub-tab** models tolerance, TCR and ageing on a divider ratio. Exact worst case (both legs at opposing extremes), RSS for the production figure, the resulting Vout window, per-leg spreads, and an effective-bits figure. It shows the TCR contribution twice — as an absolute worst case and as what survives if the two legs track — because a divider only responds to relative movement, so a matched pair cancels its own drift.

**PCB** (renamed from "PCB Power"): IPC-2221 trace width ↔ current with temperature-corrected resistance, drop and power; via ampacity/R/L/C/thermal; Onderdonk fusing current; the full IPC-2221 Table 6-1 spacing matrix including the >500 V extrapolation. **Impedance**: IPC-2141 microstrip and stripline Z₀ with validity-range warnings, ε_eff, propagation delay, wavelength, knee frequency, critical length. **Crystal**: Pierce load capacitance both directions and ppm ↔ Δf with drift. **Utilities**: AWG table; number bases (dec/hex/bin/oct, BigInt so arbitrary size is exact, with two's complement at each standard width that fits); ratio units (%, ppm, ppb, decimal); and mm/mil, °C/°F, dB/ratio.

Inputs accept SI suffixes including `4k7` style. Dimension fields on the PCB and Impedance tabs parse millimetres by default and accept `mil`, `um`, `in`, via a separate `parseDimMM`/`valDim` pair — deliberately distinct from the SI-suffix `parseVal`, because `10m` means ten metres in one context and ten milli-anything in the other.

The tool carries no organisation branding: the header, docstrings, README, `pixi.toml` authors field and the stylesheet are all neutral, and the build has no dependency outside this folder.

## Key decisions

- **Logic lives in JS, not Python.** The house rule prefers Python logic, but this page is interactive at runtime with no server, so JS is the engine and `build_page.py` is only the build harness. There is no duplicate Python implementation, so no parity test is owed.
- **No server, no launch URL.** The page opens from the filesystem; `EE_Calculator.bat` rebuilds (when pixi exists) and opens it. The generated HTML is committed so the tool works without pixi.
- **The theme is vendored, not shared.** `theme/theme.css` plus `theme/Inter.woff2` and `theme/InterTight.woff2` live in this folder, inlined at build time by the local `theme_inline.py`. The CSS is a comment-stripped copy of the shared house stylesheet (comments removed because they documented an internal brand programme). Consequence to know: **editing the shared stylesheet no longer restyles this tool** — that was the price of making it standalone and brand-free. Re-vendor deliberately if the tokens change.
- **Accent tokens: `--a-bg-accent` is a pale surface wash, `--a-on-accent` is for a solid fill.** Pairing them gives near-white on near-white. Solid fills (the selected tab) use `--a-link` + `--a-on-accent`; tinted surfaces (calculated fields, the legend chip) use `--a-bg-accent` + `--a-ink`. This was a real contrast bug caught in a browser check, not by the static tests.
- **Schematics are hand-drawn inline SVG, not Altium/LTspice exports.** Neither has a workable headless schematic-to-image path (LTspice renders only in its GUI; Altium would need the full application plus scripting per build, and its output is neither theme-aware nor self-containable). Inline SVG with `currentColor` is crisp at any zoom, follows the theme, and keeps the file self-contained.
- **IPC-2221, not IPC-2152, for current capacity.** IPC-2152's data is chart-based inside a paywalled standard; IPC-2221's equation is freely published. The card names the method and notes 2152 permits more, so the tool is conservative rather than silently wrong — the failure mode of calculators that claim 2152 while implementing 2221.
- **Impedance formulas carry validity warnings rather than false precision**, and the tab says to confirm against the fab's field solver.
- **Saturn PCB Toolkit comparison.** Assessed its whole tab list and built the four groups the user selected. Deliberately not implemented: planar inductors, embedded resistors, BGA/padstack land patterns (Altium does these), PDN target impedance, crosstalk. Differential-pair impedance was left out because the empirical formulas are markedly less accurate than the single-ended ones and would invite misplaced trust.
- `user_data/` exists and is gitignored per the tool-distribution convention, though nothing is stored there yet.

## How to continue

Edit the template in `build_page.py`, run `pixi run build`, and refresh the browser tab — there is no server to restart. Add a top-level tab with a `<button data-tab=...>` in the tab bar, a `<section class="panel" id="panel-...">`, a calc function, and an entry in the `CALCS` map; a resistor sub-tab is a `<button data-sub=...>` plus a `<div class="subpanel" id="sub-...">`. A card gets its Copy and Reset buttons automatically from the presence of a `button.reset`. To make a solver fill a field, call `setComputed(id, value)` and list the field in `clearComputed([...])` at the top of the calculator.

Verification harness (session scratch, re-creatable): a Python script extracts the page's JS, wraps it in a DOM stub whose `value` and `classList` are real, and runs assertions in node — this is what caught the field-clearing and round-tripping behaviour. The static checker cross-references every element id referenced in JS against the HTML, tabs against panels, and reset buttons against `CALCS` entries. Browser verification needs a temporary local static server, because the Chrome extension cannot open `file://` URLs.

## Open questions / blockers

None outstanding. Both questions raised at the end of the 2026-09-10 session were answered by the owner:

- **Vendored theme vs shared stylesheet — keep vendored.** The tool stays standalone and brand-free; a change to the shared house stylesheet will not reach it, and re-vendoring `theme/` is a deliberate act when the tokens change. No refresh task was added.
- **Public release — not yet, local only.** The repo stays local with no remote. The client-side-only release checks (a CSP meta tag, a scan for network APIs) and the licence decision are deferred until that changes; de-branding was done on its own merits, not as release prep.
